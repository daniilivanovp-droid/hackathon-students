## Правила работы

- `[ ]` означает «не сделано или не проверено»; `[x]` — «сделано и проверено».
- Учитывайте зависимости: SQL и документацию можно готовить параллельно с настройкой среды, но пункты интеграционной проверки нельзя отмечать до E-04; затем проверяйте `core` → `mart` → ответы.

## 2. Типизированный слой `core` — проверка после E-04

- [ ] **C-01. Проверить зерно, ключи и типы восьми таблиц.** Критерий: PK/FK соответствуют `docs/architecture.md`, деньги имеют тип `numeric`, даты типизированы, почтовый префикс — `text`.
- [ ] **C-02. Исправить категории.** Критерий: все 32 951 товара имеют непустой `category_id`; 610 товаров без категории относятся к `Non category`; две категории без исходного перевода получают согласованные подписи, португальские ключи сохраняются.
- [ ] **C-03. Исключить скрытые потери строк.** Критерий: количества семи основных таблиц `raw` и одноимённых таблиц `core` совпадают; 71 перевод покрыт в `core.categories`, которая дополнительно содержит две категории без перевода и `Non category`; дубликаты ключей и сиротские связи вызывают понятную ошибку, а не удаляются через `DISTINCT` или внутренний `JOIN`.
- [ ] **C-04. Проверить повторную сборку.** Критерий: второй запуск на том же `raw` создаёт те же таблицы и значения без ручной очистки.

## 3. Витрины — после C-01—C-03

- [ ] **M-01. Проверить `mart.order_financials`.** Критерий: одна строка на заказ; позиции агрегируются до соединения; отдельно доступны сумма цен, доставка, полная стоимость, число строк и единиц товара.
- [ ] **M-02. Проверить продажи продавцов и категорий.** Критерий: `mart.seller_sales` и `mart.category_sales` считают выручку только по своим доставленным позициям; сумма по категориям равна общей выручке, категорий в отчёте 74.
- [ ] **M-03. Проверить возвращающихся покупателей.** Критерий: `mart.customer_orders` объединяет несколько `customer_id` по `customer_unique_id` и считает доставленные заказы.
- [ ] **M-04. Расширить `mart.monthly_sales` на весь период данных.** Критерий: витрина содержит каждый месяц, встречающийся в заказах; запрос в `model/02_answers.sql` отдельно генерирует сентябрь 2016 — август 2018 и заполняет нулями отсутствующий месяц.
- [ ] **M-05. Сверить формулы в SQL и README.** Критерий: выручка — цена товаров доставленных заказов без доставки; средний чек — средняя полная стоимость доставленного заказа; доли имеют явные числитель и знаменатель.

## 4. Запуск и качество — после M-01—M-04

- [ ] **Q-01. Сделать `model/run.sh` атомарным.** Критерий: построение `core`/`mart` и проверки выполняются в одной транзакции; при сбое остаётся предыдущая модель.
- [ ] **Q-02. Проверить восемь исходных количеств.** Критерий: `orders` 99 441, `order_items` 112 650, `order_payments` 103 886, `order_reviews` 99 224, `products` 32 951, `sellers` 3 095, `customers` 99 441, переводы 71; семь одноимённых таблиц `core` сохраняют количество строк, а справочник категорий покрывает все исходные и дополнительные значения.
- [ ] **Q-03. Проверить ключи, связи, типы и категории.** Критерий: дубликат ключа, сиротская строка, неверное обязательное значение или расхождение суммы категорий останавливают сборку.
- [ ] **Q-04. Проверить контрольные ответы.** Критерий: 24 месяца, один нулевой месяц, общая выручка `13 221 498.11`, лидер продавцов `226 987.93`, средний чек `159.88`, покупатели `96 096`, повторные `3,12%`, 74 категории, крупнейшая `1 233 131.72`.
- [ ] **Q-05. Испытать повторный запуск и откат.** Критерий: два последовательных `bash model/run.sh` успешны; намеренно испорченная проверка вызывает откат, затем тестовая правка удалена.
