# Короткая записка о решениях

Мы оставили существующую структуру `raw → core → mart`: восемь типизированных таблиц отражают исходные сущности, а витрины задают уровень расчёта. От отдельной звёздной схемы отказались: для этого снимка она добавила бы дублирование и усложнила проверку строк. Модель полностью пересобирается в одной транзакции с проверками до фиксации; инкрементальную загрузку отложили до появления регулярных больших поставок.

Ключ позиции — `(order_id, order_item_id)`, платежа — `(order_id, payment_sequential)`. `customer_id` обозначает запись заказа, а повторные покупки связывает `customer_unique_id`. Покупателей и повторы считаем по всем оформленным заказам. Выручка — цена товаров только в доставленных заказах, без доставки; средний чек включает доставку и считается по заказам. Платежи и отзывы не соединяются с позициями напрямую, чтобы не размножать суммы.

Пустую категорию показываем как `Non category`; две категории без исходного перевода получают согласованные английские имена. Португальские ключи сохраняются. Месячная витрина охватывает весь период данных, а конкретный отчёт добавляет календарный ряд для пустого месяца. Приведение типов и исправления выполняются только в `core`, исходный слой `raw` остаётся неизменным.
