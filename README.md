# Кейс «Модель маркетплейса: от корзины до выкупа»

Окружение и раздаточный материал для команд. Вам предстоит спроектировать
модель данных маркетплейса, наполнить её из сырой выгрузки и ответить
SQL-запросами на вопросы аналитиков.

Данные — [Brazilian E-Commerce Public Dataset by Olist](https://github.com/olist/work-at-olist-data),
550 759 строк в восьми файлах, период с сентября 2016 по октябрь 2018.

## Быстрый старт

```bash
bash scripts/setup.sh
```

Скрипт проверяет Docker, поднимает PostgreSQL, скачивает данные, создаёт
схемы и загружает 550 759 строк в схему `raw`. На каждом шаге проверяет
результат и при сбое объясняет, что чинить.

Начать с чистого листа: `bash scripts/setup.sh --reset`

Подключение: `postgresql://hack:hack@localhost:5432/marketplace`

## Сборка модели и отчётов

После успешной загрузки `raw` запустите:

```bash
bash model/run.sh
```

Скрипт строит типизированные таблицы `core`, создаёт витрины в `mart`,
запускает проверки качества и печатает пять обязательных отчётов. Сборка и
проверки выполняются в одной транзакции: при ошибке остаётся предыдущая
модель. Повторный запуск на том же `raw` должен давать тот же результат.
Проверки останавливают сборку при потере строк, дубликатах, сиротских связях
или расхождении контрольных показателей.

В отчётах выручка — это сумма **цены товара без доставки** только по
заказам со статусом `delivered`. Средний чек — свойство заказа целиком и
включает freight. Для повторных покупок используется стабильный
`customer_unique_id` и учитываются все оформленные заказы независимо от
статуса. Пустая категория показана как `Non category`; две
категории без исходного перевода получают английские подписи, а исходные
португальские имена сохраняются. Месячная витрина охватывает весь доступный
период, а первый запрос отдельно показывает 24 месяца и ноль за пустой месяц.

## Схемы в базе

- `raw` — исходные данные как есть, все колонки `text`. Менять не нужно.
- `core` — ваша модель. Основное место работы.
- `mart` — витрины и сохранённые ответы, если понадобятся.

Все колонки в `raw` объявлены как `text` намеренно: в raw-слой данные
кладут в том виде, в каком они пришли. Объяви дату как `timestamp` —
и одно пустое значение уронит загрузку целиком. Приведение типов
и чистка это уже работа по переносу в свою модель.

## Требования к окружению

Docker Desktop или Docker Engine с плагином compose. Python 3.10+
с пакетом `psycopg2-binary` — `setup.sh` поставит его сам, если нет.
Для Windows запускайте команды в Git Bash. Проверить Python можно командой
`py -3 --version`; скрипт попробует `python3`, затем `py -3`, затем `python`
и пропустит неработающие алиасы Microsoft Store. `setup.sh` и `model/run.sh`
сами ищут Docker CLI в стандартных папках установки Docker Desktop, если его
нет в `PATH`.
SQL-клиент по вкусу: DBeaver, psql внутри контейнера или веб-клиент
pgAdmin (`docker compose --profile tools up -d`, потом
http://localhost:8080).

Логин и пароль `hack` / `hack` простые намеренно, это локальная
учебная база.

## Если что-то не работает

**Схем raw, core и mart нет в базе.** Скрипты из `scripts/init`
выполняются только при создании пустой базы. Если база уже была создана
раньше, схемы не появятся сколько ни перезапускай контейнер. Лечится:
`bash scripts/setup.sh --reset`

**DBeaver не показывает схемы, хотя скрипт отработал.** Кэш дерева.
Правый клик по соединению → Disconnect, потом подключиться заново.

**Порт 5432 занят.** Поменяйте проброс в `docker-compose.yml`
на `"5433:5432"` и запустите `bash scripts/setup.sh --reset`.

**`docker compose up` будто завис.** Образ pgAdmin весит около 400 МБ.
Он вынесен в профиль `tools` и по умолчанию не запускается — поднимайте
базу через `setup.sh`.

**Загрузка падает на `ModuleNotFoundError: psycopg2`.** Поставьте вручную:
`py -3 -m pip install psycopg2-binary` в Git Bash на Windows или
`python3 -m pip install psycopg2-binary` в Linux/macOS.

**Команда `docker` не найдена.** Установите и запустите Docker Desktop,
откройте новый Git Bash и проверьте `docker --version`. Если программа уже
установлена, добавьте каталог с `docker.exe` в `PATH`.

**Docker установлен, но daemon не отвечает.** Дождитесь в Docker Desktop
состояния `Engine running`, выберите Linux containers и проверьте
`docker info`. Посмотрите `docker context ls`; если есть `desktop-linux`,
выполните `docker context use desktop-linux`. Устаревший `DOCKER_HOST`
уберите из окружения. Для запуска через WSL проверьте WSL Integration.

**`python` открывает Microsoft Store или не запускается.** Проверьте
`py -3 --version`. При необходимости отключите алиасы `python.exe` и
`python3.exe` в настройках Windows: Apps → Advanced app settings →
App execution aliases.
